# Content Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Journal posts and publication records stored in D1, edited in an admin on `admin.oylab.uz` behind Cloudflare Access, published as pages on `oylab.uz` in three locales with primary-language fallback.

**Architecture:** One Next.js app on one Cloudflare Worker. `src/proxy.ts` splits traffic by host: the admin host is JWT-checked and rewritten to `/admin/*`, every other host runs the next-intl locale router. Content lives in D1 through Drizzle; images in a public R2 bucket; Markdown is rendered to sanitized HTML at save time by one shared pipeline.

**Tech Stack:** Next.js 16.4.5 (App Router, server actions), @opennextjs/cloudflare 1.20.16, Drizzle ORM 0.45 + drizzle-kit 0.31, D1, R2, jose 6, zod 4, unified 11 stack (remark-gfm, remark-math, rehype-katex, rehype-slug, rehype-sanitize), katex 0.19, CodeMirror 6, Vitest 5 with better-sqlite3 for query tests.

**Spec:** `docs/superpowers/specs/2026-11-04-content-platform-design.md`

## Global Constraints

- `next` stays pinned at 16.4.5; adapter 1.20.16; wrangler 4.157.0; `compatibility_date` on or before 2026-11-03.
- Worker budget: run `pnpm exec wrangler deploy --dry-run --outdir /tmp/oylab-dry` after Task 1 and Task 15; if gzip exceeds 2.5 MiB, stop and report (free-plan cap is 3 MiB).
- Locales are exactly `en`, `uz`, `ru` (`routing.locales`); English is default at `/`.
- Uzbek copy uses U+02BC (ʼ) for oʼ and gʼ, never U+02BB or an ASCII apostrophe.
- IDs are `crypto.randomUUID()`; timestamps are integer unix milliseconds; `updated_by` is the verified email, lowercased.
- Admin UI: Geist and Geist Mono only, no serif; Phosphor icons `weight="light"`; moon palette tokens from `globals.css`; touch targets at least 44px.
- Every write path is a server action returning `{ ok: true, data } | { ok: false, error: string, fieldErrors?: Record<string, string> }`; actions never throw to the client.
- Slug rules: `[a-z0-9-]`, max 80 chars, unique per table, immutable once `status = 'published'`.
- Summary max 300 characters; body max 500,000 characters; upload max 10 MB; allowed upload types image/png, image/jpeg, image/webp, image/gif, image/svg+xml, application/pdf.
- Commit after every task with a normal-prose message ending in the two attribution lines used in this repo. Run `pnpm lint` before each commit.

## Review Focus

- Publishing a post whose slug another post already uses: the action must return `fieldErrors.slug`, not throw. (Task 6 test `savePost rejects a slug used by another post`.)
- Deleting a media row that a post uses as cover: `posts.cover_media_id` must become null, not dangle. (Task 1 schema `onDelete: "set null"`, Task 7 test `deleting media clears cover references`.)
- `/journal?page=0`, `?page=-3`, `?page=abc`, `?page=999999`: page clamps to 1 or the last page, never 500. (Task 11 test `parsePage`.)
- Saving a locale tab with a body but an empty title: rejected with `fieldErrors["translations.ru.title"]`, so lists never show blank titles. (Task 8 test on `postFormSchema`.)
- A body over 500,000 characters: rejected with a field error naming the limit, not a Worker timeout. (Task 8 test on `postFormSchema`.)
